# Дорожная карта НИР: МАС в условиях неполных и зашумленных данных

## Цель

Разработать программу исследований для оценки отказоустойчивости мультиагентной
системы в условиях:

- неполных входных данных
- зашумленных входных данных
- противоречивого контекста
- потери артефактов
- сбоев коммуникации между агентами

## Основные направления

### 1. Моделирование деградации входных данных

- определить типы неполноты данных
- определить типы шума
- определить типы конфликтов во входах
- ввести уровни деградации сценариев

### 2. Моделирование сбоев в МАС

- потеря сообщений между агентами
- задержка handoff
- дублирование сообщений
- повреждение полезной нагрузки сообщений
- отказ отдельного агента
- устаревание состояния агента
- потеря или повреждение артефакта

### 3. Оценка отказоустойчивости

- измерять способность системы завершать задачу
- измерять качество деградации результата
- измерять способность системы обнаруживать ошибки
- измерять способность системы восстанавливаться после сбоя

## Этапы работ

### Этап 1. Постановка исследования

- сформулировать исследовательские вопросы
- определить гипотезы
- выбрать базовые конфигурации МАС
- определить формат сценариев и артефактов

### Этап 2. Проектирование набора сценариев

- описать классы шумов и неполноты
- задать уровни интенсивности деградации
- определить правила fault injection
- описать ожидаемое поведение системы

### Этап 3. Разработка инфраструктуры оценки

- реализовать общий runner
- реализовать сбор A2A-трасс
- реализовать сбор артефактов workspace
- реализовать автоматические checkers
- реализовать агрегатор метрик

### Этап 4. Пилотный robustness-benchmark

- собрать пилотный набор задач
- применить к ним разные типы и уровни деградации
- запустить базовые конфигурации
- проверить воспроизводимость результатов

### Этап 5. Экспериментальная оценка

- сравнить single-agent и multi-agent подходы
- сравнить системы с учётом и без учёта артефактов
- сравнить поведение на чистых и деградированных входах
- построить кривые деградации качества

### Этап 6. Анализ результатов

- выделить основные типы отказов
- определить наиболее критичные факторы деградации
- оценить вклад оркестрации и учёта артефактов
- сформулировать рекомендации по повышению устойчивости

## Ключевые артефакты исследования

- спецификация сценариев деградации
- модуль fault injection
- набор пилотных задач
- автоматические checkers
- набор baseline-конфигураций
- отчёт по метрикам и отказам

## MVP

- 20-30 задач
- не менее 5 типов деградации
- не менее 3 уровней интенсивности
- 3-4 baseline-конфигурации

## Критерии успеха

- воспроизводимый запуск сценариев
- автоматическая оценка устойчивости
- измеримые кривые деградации
- возможность сравнения разных архитектур МАС
- выявление эффекта от artifact-aware orchestration
